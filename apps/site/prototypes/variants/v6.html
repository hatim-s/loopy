From one session to a loopy

A loopy is a saved graph. You make one by doing the task for real, once, and letting Loopy read what happened.

1

Capture

Work through the task in Codex, Claude Code, OpenCode, or Pi the way you normally would. Loopy records the session as a trace, or imports one you already have.

loopy import session.json --provider codex
2

Extract

The extractor reads the trace and proposes a graph. It makes no model calls. Each node links to the trace events behind it, and nothing runs until you approve.

loopy extract --import <id>loopy approve <id>
3

Run

The graph runs on your machine through the same CLIs you captured with. State goes into local SQLite, and cron can run it every morning.

loopy run

Agents do the work. The runtime decides what runs next.

Agents work inside nodes. Everything between the nodes belongs to the runtime, so a flaky step retries instead of improvising.

Branching

A condition node reads real output and picks the edge.

Parallel joins

Fan out to several nodes. The join waits for all of them.

Retries

A failed node retries up to your limit, then stops with the error on record.

Approvals

The run parks at an approval node until a person says yes.

Pause, resume, cancel

Stop between nodes. Pick it up tomorrow, or end it cleanly.

Replay

Run a finished graph again from its recorded inputs and compare.

Checkpoint forks

Start a new run from any checkpoint without redoing the early nodes.

Schedules

0 9 * * * runs it every morning at nine.

Your laptop is the server

Loopy has no hosted compute. Source, credentials, subprocesses and traces stay on the machine that ran them.

Compute
Every node is a local subprocess. Nothing is uploaded to run.
State
Runs, checkpoints and approvals live in local SQLite.
Traces
Export any trace as JSONL and read it with whatever you like.
Schedules
