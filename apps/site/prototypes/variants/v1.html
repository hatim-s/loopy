Loopy watches you finish a task with a coding agent, turns that session into a graph you can read and edit, then runs the graph again on your machine.

$ bun add -g loopy

Recording sessioncodex ~/work/api

Capture loopy import

Do the task once in Codex, Claude Code, OpenCode or Pi. Loopy records the session, or imports one you already ran, as a trace.

Extract loopy extract

A deterministic extractor proposes a graph. No model calls. Every node points back to the trace events behind it. You review, edit and approve.

Run loopy run

The graph runs on your machine through the same CLIs. Loopy owns the order, the checks and the approvals. State lives in local SQLite.

The agent does the work. The graph decides what happens next.

Inside a node, the agent loops as long as it needs. Between nodes, Loopy runs plain rules you can read. Here is what the runtime handles for you.

Branching

Conditions route the run down one edge or another based on real output.

Parallel joins

Fan out to several nodes at once and wait for all of them before moving on.

Retries

Failed nodes retry within the limits you set, then stop with the error on record.

Approvals

The run waits at an approval node until a person says yes. Nothing gets pushed before that.

Pause, resume, cancel

Stop a run between nodes and pick it up later, or end it cleanly.

Replay

Run a finished graph again from its recorded inputs to see what changed.

Checkpoint forks

Branch a new run from any checkpoint without starting over.

Schedules

Put a loopy on cron. 0 9 * * * runs it every morning at nine.

Keep the agent you already use.

Loopy calls the CLI you have installed. Your login, your model settings and your config stay as they are. Mix providers inside one graph if you like.

It all runs on your machine.

There is no hosted compute. Loopy is a process on your laptop that starts other processes on your laptop.

  • Source, credentials, subprocesses and traces stay local.
  • Run state lives in a SQLite file inside your project.
  • Traces export as JSONL, so you can read them with any tool.
  • Open source under Apache-2.0.
